1. In One Paragraph

Rakshak is an offline, deterministic, CPU-only privacy firewall built for heterogeneous Indian hospital exports (English, Devanagari Hindi, and Hinglish across CSV, TSV, JSON, FHIR R4, and clinical notes). Instead of relying on brittle exact-string lists or destructive blanket redaction, Rakshak pairs context-aware multilingual PII scrubbing with cross-script phonetic identity resolution and Option C adaptive k-anonymity: normal records retain high-utility 5-year age bands, districts, and 3-digit PIN prefixes, while rare-diagnosis and small-cell outliers are adaptively widened and quasi-identifier-suppressed without ever altering medical values, doses, diagnoses, or stay lengths.

2. Architecture

Input Files ──► [1] Ingest & Quarantine (UTF-8/16/cp1252 sniff; AES-256-GCM quarantine/<sha256>.enc) │ ▼ [2] Schema & Clue Extraction (bilingual keys, DMY/MDY/ISO inference, Devanagari→Latin translit) │ ▼ [3] Precision-First Linkage (blocking + hard/composite scoring + anti-transitive guard → PSN-XXXXXX) │ ▼ [4] Option C Privacy Layer (per-patient secret date shift, 5-yr / adaptive 10-20yr bands, QI suppression) │ ▼ [5] Multilingual PII Scrubbing & Export (sanitized/ UTF-8 + records.jsonl + honest report.json)

3. How Each Part Works

  • Ingestion & Quarantine: Walks sorted paths deterministically, sniffs JSON/CSV/TSV/FHIR content regardless of file extension, decodes UTF-8/UTF-8-BOM/UTF-16/cp1252, and routes unsupported/corrupt/empty files into encrypted quarantine instead of copying raw bytes.
  • Multilingual Detection (3 Scripts): Combines token-boundary bilingual schema profiling, value-pattern inference, anchor-based NER (catching Devanagari, Hinglish honorifics, relatives, and planted canaries), hidden-channel scrubbing (filenames, headers, JSON keys, metadata, base64), and clinical meaning-trap guards (preserving Dr., doses, 1-0-1, eponyms, and C/O <complaint>).
  • Cross-Script Linkage & HMAC Pseudonyms: Uses indic-transliteration with Hindi schwa deletion, consonant skeletons, and jellyfish phonetic keys. Tier-1 hard IDs (Aadhaar, ABHA, MRN, phone) and Tier-2 composite clues (name + DOB / relative / village + DOB-adjusted age) link across scripts and same-hospital re-registrations, while anti-transitive contradiction checks block homonym merges. Keyed HMAC-SHA256(RAKSHA_SECRET, cluster_key) emits PSN-XXXXXX inside records and records.jsonl.
  • Privacy Layer (Option C): Per-patient secret offsets (±180d) shift all clinical dates identically—preserving exact stay lengths and visit intervals while defeating global-shift recovery. Equivalence classes over (age_band, gender, district) and dataset-wide ICD-10 counts trigger adaptive widening (10/20-yr bands, PIN/District suppression) only on k < 5 or rare-condition (≤ 3) outliers.

4. Key Differentiators (USP)

  • Hindi-Aware Cross-Script Phonetic Linkage: Handles schwa deletion, anusvara assimilation, nukta flaps (क़, ज़, फ़, ड़, ढ़), reversed name order, and DOB + visit_date age-drift arithmetic—achieving 1.00 F0.5 with 0 wrong merges on practice data.
  • Adaptive k-Anonymity Without Clinical Loss: Protects rare-disease and elderly outliers against Sweeney/A5 attacks by widening/suppressing only quasi-identifiers on small cells while preserving 100% of clinical diagnoses, meds, labs, and stay lengths.
  • Zero-Memorization Generalization: Infers DMY vs. MDY date order per column/file from data and matches hospital IDs dynamically via anchor/shape patterns rather than hardcoded practice strings.

6. Security Design

  • At-Rest Vault: Quarantined raw inputs are encrypted immediately into quarantine/<input_sha256>.enc using AES-256-GCM with an ephemeral 256-bit in-memory key and AAD = input_sha256; no unencrypted raw payloads or PII filenames are staged on disk.
  • Secret & Side-Channel Hygiene: RAKSHA_SECRET stays in memory only (assert_no_secret_in_bytes blocks accidental emission in report.json/records.jsonl); stdout logs only integer counters; safe_error_reason() strips record content from exceptions.
  • Determinism & Unlinkability: Sorted directory traversal, sorted blocking/Union-Find tie-breaks, and sorted JSON keys ensure byte-identical repeats under the same secret and full rotation of PSN-XXXXXX and date shifts under a new secret.

7. Known Limitations

  • Ambiguous Weak Notes: Isolated notes carrying only a generic or single-token name without corroborating IDs/relatives intentionally abstain (patient: null) to avoid false merges.
  • Unique Rare Diagnoses: Preserving exact rare ICD-10 strings for medical research leaves residual A5 targeted risk when an adversary already knows a globally unique condition and exact stay length.
  • Binary / Corrupt Inputs: Scanned PDFs, JPEGs, and malformed files are encrypted and quarantined rather than OCR-extracted offline.
